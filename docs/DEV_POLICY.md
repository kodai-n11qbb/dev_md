# DEV_POLICY.md

AIエージェントとの対話による設計・実装協働プロトコル。

---

## 1. 目的とスコープ

- 目的: 人間とAIが対話しながら目的・仕様を固定し、テストを伴う最小限の高品質な実装を行う。
- 対象: 本リポジトリのドキュメントおよびソースコード。
- 原則: **ファイル丸読みの禁止（Selective Loading）** と **トークン効率の極大化**。

---

## 2. フェーズ定義

### PHASE_0: ファストトラック（軽微修正・単一ファイル対応）
- **トリガー**: タイポ修正、軽微なCSS/UI調整、既知の単一バグ修正。
- **AIの役割**:
  - 設計書の更新・スキル読み込みは原則不要。
  - 方針を人間と1往復で合意したら、直接対象ファイルを修正してスピーディーに完了させる。

### PHASE_1a: 目的設定・意図整理フェーズ（対話のみ）
- **トリガー**: 人間が「〜したい」「〜どうする？」「〜作って」「〜について考えて」と発話。
- **読み込むスキル**: `.agents/skills/goal-setting`
- **鉄の原則**:
  - **コードは1行も書かない。設計書もまだ更新しない。対話を止めない。**
  - 人間が焦って「実装して」と発話した場合でも、目的（Why）と完了条件（DoD）が未定の場合は、「目的と完了条件のみ1点確認させてください」と立ち止まり、手戻りを防ぐ。
- **完了要件**:
  - Why / Who / Non-Goal / DoD の要約を人間に提示し、承認（「OK」「それでいこう」）を得る。

### PHASE_1b: 設計文書化フェーズ（仕様固定）
- **トリガー**: PHASE_1a で方針が合意された直後（AIから自律的に提案・実行）。
- **AIの役割**:
  - 合意内容を `docs/` 配下の該当設計書にピンポイントで反映する。
  - 設計書を新規作成した場合は、後述のナレッジグラフ（Graphify）等で追従する。

### PHASE_2: コミットフェーズ
- **トリガー**: 設計固定後、または実装フェーズ完了時。
- **AIの役割**: `ai(docs): ...` または `ai(feat): ...` の形式でコミットを提案・実行する（pushは人間の明示指示がない限り行わない）。

### PHASE_3: 最小実装・テスト駆動フェーズ
- **トリガー**: PHASE_1b完了後、または人間からの実装指示。
- **読み込むスキル**: `.agents/skills/ponytail`, `docs/CODING_RULES.md`
- **AIの必須手順**:
  1. 該当する設計書、または `.agents/skills/graphify` のナレッジグラフから対象依存関係のみを確認。
  2. テスト環境が未構築の場合、最小限のテストランナーを導入。
  3. Ponytail 7段階ラダーに準拠し、境界値・異常系テストと最小限のコードを実装。
  4. テスト実行により DoD が満たされたことを確認し、人間に報告。

---

## 3. 例外規定
- 緊急対応等で設計を完全にスキップして実装を行う場合は、`docs/decision-log.md` に設計例外として記録を残す。
