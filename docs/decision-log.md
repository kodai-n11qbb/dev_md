# decision-log.md (ADR: 意思決定記録)

プロジェクトにおける技術選定、ツールの試用・導入判定（Spike）、設計例外の決定経緯を簡潔に記録する。
**AIはツール試用前に本一覧を確認し、過去に検証済みのツールの再検証を行わないこと。**

---

## 記録フォーマット

```markdown
### [YYYY-MM-DD] タイトル（例: ツール試用: ライブラリ名 / 設計例外）
- **ステータス**: 採用 / 見送り / 例外承認
- **用途・背景**: なぜ検討したか
- **検証結果・判断理由**:
  - メリット:
  - リスク・デメリット:
- **結論**: 今後の方針（採用時は利用コマンドやスクリプトパスを記載）
```

---

## 記録一覧

### [2026-11-02] CLIベースのセキュリティチェックスキル（security-check）の導入
- **ステータス**: 採用
- **用途・背景**: AIエージェントによるコード生成におけるセキュリティ脆弱性（シークレット漏洩、危険な依存パッケージ、重大バグ）を機械的に防止するため。
- **検証結果・判断理由**:
  - メリット: LLMにコードを丸読みさせず、ローカルCLI（Gitleaks, Trivy, Semgrep等）を実行させることで、トークン消費ゼロかつ高速にCVSS 7.0以上（High / Critical）の即死級脆弱性を約85〜90%カバーできる。
  - リスク・デメリット: 業務ロジックの脆弱性（権限チェック漏れ等）はカバーできないため、過信は禁物。
- **結論**: `.agents/skills/security-check` として導入し、PHASE_4（またはリリース前ガードレール）として運用する。
