# Ponytail スキル（最小実装・YAGNI強制プロトコル）

> **哲学**: "The best code is the code you never wrote."（書かないコードが最善のコードである）

本スキルは実装（PHASE_3）時にロードされ、AIエージェントの無駄なコード生成・不要なライブラリ追加を徹底的に防ぐ。

---

## 1. 7段階の判断ラダー (The Decision Ladder)
コードを書く前に、必ず以下のラダーを上から順に評価し、**最初に該当した最上位の手段を採用して即座に終了する**こと。

1. **YAGNI (You Aren't Gonna Need It)**:
   - この機能・コードは本当に今必要か？不要なら書かずにスキップする。
2. **既存コードの再利用 (Existing Codebase)**:
   - リポジトリ内の既存関数・共通ロジックで実現できないか？あれば再利用する。
3. **標準ライブラリの活用 (Standard Library)**:
   - 言語の標準機能（組み込み関数、標準モジュール）で実装できないか？
4. **プラットフォーム・ネイティブ機能 (Platform Features)**:
   - OSやブラウザの標準API（例: `<input type="date">`, `fetch()` 等）で解決できないか？
5. **導入済み依存関係 (Installed Dependencies)**:
   - すでに `package.json` 等に導入されている既存ライブラリで解決できないか？（新規パッケージの追加は原則禁止）
6. **1行解決 (One-Line Solution)**:
   - 複雑なヘルパーやクラスを作らず、1〜数行の簡潔な式で表現できないか？
7. **最小限の自作実装 (Minimum Implementation)**:
   - 上記のすべてが不可能な場合のみ、必要最小限のコードを自作する。

---

## 2. アーキテクチャの鉄則
- **Dependency Injection (DI)**: 具象クラスを直接 new せず外から渡せるようにし、テスト容易性を担保する。
- **Rule of Three**: 同じコードが3回出てくるまで、性急な共通化・抽象化を禁止する。

---

## 3. 業界標準のテスト・品質保証（削ってはいけない領域）
Ponytail はコードの無駄を削るが、**品質保証（テスト）を削ることは厳禁**とする：
- **テスト環境の自己構築**:
  - テスト環境が存在しない場合は、**実装コードを書く前にまず最小限のテストランナー（Vitest, pytest等）をセットアップすること。**「環境がないため省略」は禁止。
- **テスト必須要件**:
  - 正常系だけでなく、**境界値（Boundary）**および**異常系・エラーハンドリング**のテストを必ず添付する。
- **型安全性・静的解析**:
  - 型定義を省略しない。Linter / Formatter があればエラーゼロを確認して完了とする。
