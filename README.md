# dev_md

AIコーディングエージェント（Antigravity, Cursor, Claude Code等）の過剰実装・トークン浪費を抑止し、仕様合意・テスト駆動・最小実装を強制するためのルールおよびオンデマンドスキルセット。

---

## 背景と課題

LLMを用いた自律コーディングにおいて頻発する以下の問題を、プロンプトとディレクトリ構造によって機械的に抑止する：

1. **意図が未確定なままの実装開始**: 目的や完了条件（DoD）が曖昧な状態でコードを生成し、大幅な手戻りが発生する。
2. **過剰実装（Bloatcode）**: 不要な外部パッケージの追加や冗長なラッパー層の作成により、コードベースの保守性が低下する。
3. **コンテキストの浪費**: ドキュメントの全件読み込みや無制限のファイル走査により、トークン消費と推論遅延が増大する。
4. **テストの省略**: テスト環境が存在しないことを理由に、動作保証コードを省略する。

## 構成

リポジトリ直下に配置する最小構成（約250行）：

```text
.
├── AGENTS.md                                # 自動認識されるエントリーポイント（フェーズ分岐ルーター）
├── .agents/skills/                          # フェーズ別オンデマンドスキル（How to work）
│   ├── goal-setting/SKILL.md                # PHASE_1a: 目的設定・対話ブレーキ（Why/Who/Non-Goal/DoD）
│   ├── graphify/SKILL.md                    # PHASE_2: ナレッジグラフによる構造探索（丸読み抑止）
│   ├── ponytail/SKILL.md                    # PHASE_3: 7段階判断ラダー・最小実装・テスト義務化
│   └── security-check/SKILL.md              # PHASE_4: CLI脆弱性スキャン・CVSS 7.0+ブロック
└── docs/                                    # プロジェクト固有の記録・管理（What & Why）

    └── _meta_guide.md                       # ルール保守・自己進化ガイド
```

## エージェントの制御フロー

人間の発話・入力に応じて、エージェントは以下のフェーズで動作する：

| フェーズ | トリガー | 読み込むスキル/規約 | 動作制約 |
| :--- | :--- | :--- | :--- |
| **PHASE_0** | 軽微な修正（タイポ、CSS/単一バグ修正） | 直接修正 | ドキュメント更新・スキル読込をスキップし、即座に修正・完了する。 |
| **PHASE_1a** | 要件検討・「〜したい」「〜作って」 | `.agents/skills/goal-setting` | **コード・設計書は書かない。** Why / Who / Non-Goal / DoD を整理し、要約合意をとる。 |
| **PHASE_1b** | 方針合意後 | 該当設計書（`docs/` 配下） | 合意内容をピンポイントで設計書に固定する。 |
| **PHASE_2** | 構造把握・既存調査 | `.agents/skills/graphify` | ファイルの丸読みを行わず、グラフ依存パスを探索する。 |
| **PHASE_3** | 実装・テスト | `.agents/skills/ponytail` | 7段階判断ラダーで最小限の実装を行い、テスト実行（ALL PASS）を確認して納品する。 |
| **PHASE_4** | セキュリティ検査・リリース前 | `.agents/skills/security-check` | CLIツール（トークン最小）でHigh/Critical（CVSS 7.0+）を検出し、該当箇所のみ修正する。 |

---

## 主な制約事項

- **Ponytail 7段階判断ラダー**:
  コード作成前に `YAGNI` → `既存コード再利用` → `標準ライブラリ` → `プラットフォーム標準API` → `導入済み依存` → `1行解決` → `最小限の自作` の順で評価し、最上位を採用する。
- **テスト義務化 & 実行検証（Run & Verify）**:
  テスト環境が存在しない場合、実装前に最小限のテストランナーを自己導入する。テスト作成後は必ずローカルで実行し、エラーゼロ（ALL PASS）を確認して納品する。
- **Spike撤退リミッター**:
  ツール・ライブラリの検証で2回連続失敗した場合、深追いせず即座に標準実装に切り替える。結果は `docs/decision-log.md` に1行記録する。
- **コミット前グラフ同期**:
  コードや設計書を変更した際、**`git commit` の直前に1回 `graphify .` を実行**してナレッジグラフを最新化する（作業途中の都度実行は不要）。

## 導入と運用

### 別プロジェクトへの導入（推奨: AI自動セットアップ）

対象プロジェクトのルートで一時クローンし、[HANDOVER.md](file:///Users/abekoudai/Desktop/dev_md/HANDOVER.md) をAIに渡すだけで完了します：

```bash
git checkout -b setup-dev-md
git clone https://github.com/kodai-n11qbb/dev_md.git .tmp_dev_md
```

AIチャットで以下を送信（メンションするだけで全自動実行）：
> `@.tmp_dev_md/HANDOVER.md`
> （または「`.tmp_dev_md/HANDOVER.md` を読んで」）

AIが確認や質問を挟むことなく、必要なファイル（`AGENTS.md`, `.agents/skills/`, `docs/`）の配置、環境判定、一時ディレクトリの削除まで一気通貫で完遂します。

---

### 手動導入
1. **配置**: `AGENTS.md`, `.agents/`, `docs/` を対象プロジェクトのルートディレクトリに手動でコピーする。
2. **実行**: エージェントを起動すると `AGENTS.md` が自動認識され、入力内容に応じたスキルがオンデマンドでロードされる。
3. **拡張**:
   - 仕様書が必要な場合: `docs/` 配下に実体ファイル（`architecture.md` 等）を追加する。
   - 新規スキルが必要な場合: `.agents/skills/<skill-name>/SKILL.md` を追加し、`AGENTS.md` に登録する。
   - ルール改定: エージェントに「ルールを見直して」と指示し、`docs/_meta_guide.md` に基づいて保守を行う。
